# E004: Hardware Preconditions, Bank Safety, and Re-entrancy

Aun enforces hardware and memory safety at compile time:

- **Bank & Interrupt Preconditions**: Functions or `extern "asm"` symbols annotated with `requires bank(Name)` or `requires di` must only be called inside an active `with bank(Name) { ... }`, `critical { ... }`, or `#[interrupt(...)]` ISR context where interrupts are disabled or compatible banks are mapped. Overlapping banks in the same `bank_group` cannot be active simultaneously.
- **ISR Ownership & Lock-Free SPSC Queues**: Globals annotated with `#[owned_by(IrqSource)]` may only be accessed directly from that `#[interrupt(IrqSource)]` ISR or inside a `critical { ... }` (or `di`) section; unguarded main-thread access is rejected at compile time. `Queue<T, N>` enforces single-producer / single-consumer (SPSC) ownership statically so an ISR producer and main-thread consumer (or vice versa) can pass events via `.push(...)` / `.pop(&mut out)` / `.is_empty()` / `.len()` without `critical` blocks; multi-producer or multi-consumer access is rejected.
- **State Machine Transitions**: Under `#[strict_transitions]`, dynamic `m.goto(...)` on an unnarrowed machine is rejected; narrow via `match` or call `goto` inside `on <State>`.
- **Recursion & ISR Isolation**: *Uchiguri* places non-`#[reentrant]` locals in static RAM. Recursive calls require `#[reentrant]`, and non-`#[reentrant]` functions cannot be shared between main-thread code and `#[interrupt(...)]` ISRs. *Uchiguri* also keeps `#[interrupt(...)]` subgraphs strictly separated from main-thread RAM, conservatively edges indirect `addr_of(fn)` calls to all address-taken targets, and protects external C calls against `pub fn` re-entry callbacks in `--format sdasz80` builds.

See [Target Definitions and Uchiguri RAM](../target-and-memory.md) for full rules.
