# E006: Code and Overlay Budget Overflow

This error occurs when `Resident` code or an overlay blob (`#[swap_boundary]` / `#[overlay]`) does not fit within the remaining address window of its target `space`, `bank`, or `overlay_slot`.

## Do NOT Rewrite to Assembly First

Before opening `.asm` files or rewriting Aun code in assembly, inspect the structural placement with:

```sh
aun build --memory-report ...
```

`--memory-report` completes even when a blob exceeds its budget and prints:
- How much of the target `space` is occupied by `Resident`, parent overlays, and each child overlay.
- Top symbols per region (functions, `const` tables, external `.s`).
- **LCA promotion callers**: which state calls forced a helper or `const` table up into `Resident` or a parent overlay.

## Recommended Fix Order

1. **Remove unused/demo data**: check `warning[W001]` and top `const` tables in `--memory-report`.
2. **Shrink Resident / parent FSM first**: every byte removed from `Resident` or a parent `#[swap_boundary]` increases the budget for *all* child overlays. Break stray cross-state calls shown under `LCA-promoted`.
3. **Split into deeper `#[swap_boundary]` subtrees**: move mutually exclusive scenes, `const` tables, and `[overlay_asm]` `.s` modules into sibling boundary states so they share the same RAM window.
4. **Use `#[smc]` on singleton FSMs**: keeps per-state dispatch tables inside overlays and omits `*_vtbl_*` from Resident.
5. **Relocate to secondary `space` or `bank`** if the target provides additional memory windows.

See [Memory & Overlay Budget Optimization Playbook](../memory-optimization.md) (`aun guide memory-optimization`) for the full checklist.
