# E005: Overlay Isolation, State-Scoped Buffers, and Space Budgets

When using `#[swap_boundary]`, `#[overlay(...)]`, or state-scoped `static mut` buffers, Aun guarantees statically that no code calls into an unmapped overlay or accesses a state buffer outside its active lifetime.

## Common Errors & Fixes

1. **`illegal cross-overlay call from ... to ...`**
   - A function or `extern "asm"` symbol owned by one boundary subtree (such as `App::Stage1`) is called directly from Resident code or from a sibling subtree (`App::Stage2`).
   - **Fix**:
     - If multiple sibling states intentionally share the helper (for instance `Stage1` and `Stage2` inside `InGame`), place `#[overlay(App::InGame)]` (or assign the `.s` file to `App::InGame` in `[overlay_asm]`) and remove explicit `#[overlay(App::Stage1)]` pins—for regular `fn`s without explicit pins, the compiler already promotes common helpers to their call-graph LCA automatically.
     - If transitioning between mutually exclusive scenes, use `goto Stage2 { ... };` (or `m.goto(...)`) so execution jumps safely through a Resident swap trampoline.

2. **`cannot access state-scoped buffer ... outside its owning state`**
   - A `static mut BUF: ...` declared inside `state S { ... }` can only be read or written inside `on S { ... }` or descendant states of `S`.
   - **Fix**: Move the buffer up to a common ancestor state (or top-level `static mut`) if an outer context needs it, or expose an accessor method on `on S`.

3. **`conflicting overlay ownership for extern ...`**
   - An `extern "asm"` function has `#[overlay(StateA)]` in `.aun` while its implementing `.s` module is assigned to `StateB` via `--asm` or `[overlay_asm]`.
   - **Fix**: Align the attribute and `--asm` / `[overlay_asm]` state path, or remove the redundant pinning so both agree.

4. **`overlay ... exceeds ... budget`**
   - Combined code, ROM constants, and external `.s` data inside a boundary blob exceed the remaining window of its target `space`, `bank`, or `overlay_slot` (clamped below Resident `ram_base`, stacks, and non-owning bank windows).
   - **Fix**: Move cold or large scenes into deeper `#[swap_boundary]` subtrees so siblings reuse the same address window, or move blobs/buffers into a secondary `space` or switchable `bank`.
